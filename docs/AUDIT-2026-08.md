# Plaster Code Audit — August 2026

Six parallel deep reviews (wall, messaging, screens, edge functions, clipper/admin,
shared infra + migrations), findings verified against the code. Ranked by what
actually matters. Check items off as they're fixed.

---

## Tier 1 — Security (fix immediately; all server-side, live on deploy)

- [x] **push-notification: no caller authentication.** FIXED 2026-08-22 — shared `WEBHOOK_SECRET` (x-webhook-secret header) required; forged anon-key calls now 401, real triggers 200. Verified live E2E. Anyone with the public anon
  key can POST a forged payload and deliver arbitrary push notifications (phishing
  text included) to any user's phone. Same class: **report-alert** (worse — a forged
  `target_id` makes the service role read ANY private message body and email it out)
  and **va-decision-alert** (email any user from an unverified payload).
  Fix: require a shared `x-webhook-secret` header on all webhook-shaped functions,
  set the secret in the DB webhook config.
- [x] **fetch-image: open server-side proxy.** FIXED 2026-08-22 — admin-gated + private/link-local host blocklist + 8s timeout + 12MB cap. No auth, no host restrictions, no
  timeout, no size cap — can be pointed at internal network addresses and used to
  probe/proxy from Supabase's infrastructure. Fix: copy resolve-music-embed's
  pattern (auth + allowlist + 6s timeout + size cap).
- [x] **submit-community-post: user-controlled mimeType uploaded unvalidated** FIXED 2026-08-22 — mime whitelist (jpeg/png/webp/gif) + 20MB cap; extension derived from validated mime. to the
  public posters bucket (could host non-image active content); moderation failure
  currently fails OPEN. Fix: enforce `/^image\//`, cap size, fail closed.

## Tier 2 — Bugs real users will hit (app-side unless noted)

- [ ] **Auth refresh wipes half the app.** `AuthContext.onAuthStateChange` ignores the
  event type: every hourly token refresh / iOS foreground-resume nulls `profile`,
  re-fetches it, and re-renders every consumer. Visible: LINE UP blanks to
  "Loading…" on every app reopen (4 channels torn down + refetch), an in-progress
  bio edit is silently wiped, admin UI flickers out. Fix: only react when the user
  id actually changes; memoize context value + `refreshProfile`.
- [ ] **MSG badge counts messages you're actively reading.** `last_read_at` is only
  set on thread open, never while it's open — the badge increments as your friend
  messages you mid-conversation and stays wrong after you leave.
- [ ] **Sends can fail silently.** Composer clears before the insert; the error path
  does nothing, and even successful sends only render via the realtime echo (often
  seconds-dead after iOS resume) → users re-send → real duplicates. Fix: append
  locally on success, restore text + surface error on failure.
- [ ] **Incoming messages force-scroll the reader to the bottom** even when scrolled
  up reading history (the proximity guard exists in the ResizeObserver path but not
  the message-arrival path).
- [ ] **Inbox realtime can't ADD conversations.** A first-ever message from someone
  new (or a dismissed conversation the DB restores) never appears while sitting on
  the MSG tab — badge and inbox disagree until remount.
- [ ] **International contacts never match.** `normalizePhone` assumes any 10-digit
  number is US *before* checking for a `+` country prefix — Danish/Norwegian/etc
  contacts hash wrong and silently never match. Fix: check `+` first. (Also:
  onboarding phone-save ignores the supabase error return.)
- [ ] **1-col wall loads every poster at full resolution at once** (two eager imgs
  per event, no lazy/windowing) — with a 300-event page that's ~600 simultaneous
  full-res requests; the multi-col path's own comment documents this exact failure
  (ERR_INSUFFICIENT_RESOURCES). Memory risk on iOS as the DB grows.
- [ ] **Per-card fetch of the user's ENTIRE post-like history** (no event scoping,
  no limit) on every card activation — unbounded growth with usage.
- [ ] **"Attended" stat caps at 24 forever** (limit-24 list length used as the total;
  the is_official branch does a real count — copy it). Same in AccountProfile.
- [ ] **Venue-profile date labels use hour-diff math** — tonight's 8pm show viewed at
  7am says "Tomorrow" (`Math.round(hours/24)`; compare local calendar days instead).
- [ ] **Wall "Tonight"/day labels use device timezone** — an East Coast visitor sees
  Portland shows filed under the wrong day. Low priority pre-travel-audience.
- [ ] **Pagination cursor has no tiebreak** — events sharing the exact boundary
  timestamp (many shows at 8:00 PM) can be silently skipped at page edges.
- [ ] **Filtered-short wall can't load more** — a filter matching few of page 1 never
  scrolls, so `loadMore` never fires and deeper matches are unreachable.
- [ ] **Like/unlike isn't atomic** — double-tap can permanently drift `like_count`
  (counter RPC commits even when the insert no-ops).
- [ ] **Auth resend-cooldown stacks intervals** (start → "different email" → start
  again = 2× speed countdown + leaked timer). One-line fix.
- [ ] **No error boundary above the router** — a stale client requesting an old chunk
  after a redeploy gets a permanent white screen. Wrap AppRoutes; add a reload
  fallback on chunk-load failure. (AuthContext also swallows profile-fetch errors →
  a single failed fetch can blank-screen /auth for the session.)

## Tier 3 — Scale & cost (not urgent at friends-scale; will bite as usage grows)

- [ ] **LINE UP: four unfiltered global subscriptions** (`attendees`,
  `event_wall_posts`, `event_likes`, `follows`, event `*`) — any activity by ANY
  user refetches every viewer's feed (and blanks it to "Loading…"). Debounce,
  keep stale content visible, filter or poll.
- [ ] **FollowButton opens one unfiltered `follows` subscription per instance** —
  40 matched contacts = 40 subscriptions, each change firing 40 RPCs. Share one
  filtered subscription via the existing userRelationStore pattern.
- [ ] **BottomNav: unfiltered `messages` subscription per client** + RPC per event
  (incl. own sends). MsgScreen holds a second one. O(clients × message volume).
- [ ] **Missing DB indexes** on hot paths: `events(venue_id)`, `attendees(user_id)`,
  `event_likes(user_id)`, `events(recurrence_group_id, starts_at)` (the last one
  makes the publish trigger seq-scan events per row during Approve All).
- [ ] **Ingest: AI enrichment runs BEFORE dedupe** — re-fetching an already-imported
  page burns up to 60 Firecrawl + 60 Haiku calls to insert nothing. Check the
  cheap dedupe index first.
- [ ] **No DB unique constraint backs ingest dedupe** — two overlapping runs
  (double-click, retry) can both insert. Consider a unique index on
  (venue_id, portland_date, normalized_title) or advisory locks.
- [ ] **Missing AbortSignal timeouts** on several Anthropic calls (composeDescription,
  extract-poster main call, others) — one hung connection strands a half-inserted
  batch. The Firecrawl calls do it right; copy them.
- [ ] **MapScreen:** radius circle + fog GeoJSON recomputed and re-serialized every
  pan frame when radius < Any (useMemo on [lat,lng,radius]); tab switches fully
  re-init Mapbox (billable map load + ~1s) and refetch everything.
- [ ] **LINE UP fetches the user's entire RSVP history** (incl. all past events) on
  every mount; filter server-side to upcoming.
- [ ] **MsgScreen:** unbounded message load per thread (no limit) + one
  last-message query per conversation on every inbox load (N+1).
- [ ] **portlandOffset month heuristic** wrong ~3 weeks/year around DST switches —
  late shows near the boundary can store an hour off / wrong dedupe date.
- [ ] **Storage orphans:** several upload-then-insert paths leave public files behind
  when the DB write fails (ingest, community posts, review editor, splash). Cheap
  fix: remove-on-error; someday: a GC sweep.

## Tier 4 — Clipper & admin tooling (only affects Rob)

- [ ] **chrome.storage log races** — concurrent captures + panel writes can eat each
  other's updates (card stuck at "reading…", dismissed cards resurrect). Serialize
  mutations through the background worker.
- [ ] **ImportForm double-submit window** during the dup-check await → duplicate
  inserts (×12 with recurring). Set a synchronous `submitting` guard.
- [ ] **Failed ingest destroys the staged poster** (retryPayload only kept for
  duplicate/confirm results — keep it on error too).
- [ ] **retryPayload bloat**: multi-MB base64 stored per card, whole-array rewritten
  on every change; move payloads to per-entry keys.
- [ ] **DuplicateVenueMerger**: non-transactional + fully silent failure (half-merged
  DB with no error shown). Surface errors like DuplicateEventMerger does.
- [ ] **AdminPendingEvents batch actions** ignore per-row errors (silent partial
  failures). AutoIngest backfill button isn't disabled while running (double spend).
- [ ] **Clipper badge timers** overwrite each other (can hide a DUP/ERR signal);
  **regionMode** is global across tabs (cross-tab grab mixes modes); force/confirm
  replay can double-fire after a panel re-render.
- [ ] **Clipper token**: static long-lived secret grants pending-deletes of any event;
  non-constant-time compare; fine for a single-operator tool, revisit before anyone
  else gets the extension.
- [ ] **extract-poster**: model output interpolated into an ilike pattern (wrong-venue
  matches on substrings); the AI address fallback is the source of the known
  "Showbar wrong address" class of bugs — consider dropping fallback 3.
- [ ] **delete-my-account** scrubs before deleting auth — a failure between leaves a
  live login with scrubbed content; make the destructive step last.
